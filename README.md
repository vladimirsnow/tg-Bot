# Telegram-бот для видео, фото и музыки

В разрешённой группе и в личке с владельцем бот автоматически обрабатывает ссылки из текста и подписей к вложениям. Он отправляет видео как MP4, фотографии как альбом, а звук фотопоста отдельным MP3 после фотографий, если площадка отдаёт этот звук. Поддерживаются Instagram Reels и посты, TikTok и его короткие ссылки, YouTube Shorts и обычные видео YouTube, посты X/Twitter с медиа.

Чтобы найти трек, напиши `@имя_бота Исполнитель — Название`. Бот ищет полное аудио через YouTube, SoundCloud и Audius. Лучше указать исполнителя, особенно если у разных песен одинаковые названия.

## 1. Подготовь бота

1. В Telegram напиши [@BotFather](https://t.me/BotFather) и создай бота командой `/newbot`. Скопируй токен.
2. У того же BotFather вызови `/setprivacy`, выбери бота и нажми `Disable`. Добавь бота в группу. Если он уже там, удали его из группы и добавь повторно. Для чтения ссылок админка ему не нужна.
3. Распакуй архив. В папке `telegram-media-bot` скопируй `.env.example` в `.env` и впиши токен в `TELEGRAM_BOT_TOKEN`. Если `BOT_TRIGGER` пустой, используется текущее `@имя_бота`. Можно задать свой триггер, например `BOT_TRIGGER=музыка`.

## 2. Запусти на хостинге

### Oracle Cloud Always Free

Создай бесплатный аккаунт [Oracle Cloud](https://www.oracle.com/cloud/free/). При регистрации нужна карта для проверки. В домашнем регионе создай виртуальную машину Ubuntu 24.04 с конфигурацией `VM.Standard.A1.Flex`, 1 OCPU, 4 ГБ ОЗУ, стандартным диском и публичным IPv4. Проверь метку `Always Free Eligible`. Oracle может забрать малонагруженную бесплатную машину, а свободных мест на A1 в регионе иногда нет. [Условия Always Free](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).

Зайди по SSH. Установи [Docker Engine и Compose](https://docs.docker.com/engine/install/ubuntu/) на виртуальную машину. Перенеси туда распакованную папку, например через `scp`, и выполни команды из неё.

```bash
cp -n .env.example .env
chmod 600 .env
nano .env
sudo docker compose up -d --build
sudo docker compose logs -f --tail 30 bot
```

Контейнер автоматически запускается после перезагрузки сервера. Бот сам запрашивает новые сообщения у Telegram, поэтому для него хватает исходящего доступа в интернет. Для управления сервером нужен SSH.

### Northflank Developer Sandbox

[Northflank Sandbox](https://northflank.com/pricing) предлагает бесплатный объём ресурсов на месяц и сервисы без сна. Для создания сервиса потребуется способ оплаты. Оставайся в Sandbox, проверь выбранный размер контейнера и следи за учтённым трафиком, прежде чем менять тариф. На маленьком контейнере перекодирование больших роликов может занимать дольше.

1. Загрузи исходники в приватный Git-репозиторий. Оставь `.env` и cookies на своём компьютере.
2. Создай проект Sandbox и один [Combined Service](https://northflank.com/docs/v1/application/getting-started/build-and-deploy-your-code). Выбери репозиторий, Dockerfile из корня и один экземпляр. Публичные порты не нужны.
3. Перенеси значения из `.env` в **Runtime Environment Variables**. `TELEGRAM_BOT_TOKEN` храни как секретную переменную. После изменения переменных проверь, что сервис перезапустился.

### Render Free с автоматическим пробуждением

Бесплатный Render засыпает после 15 минут без входящих запросов. В этом репозитории есть GitHub Actions workflow, который обращается к `/health` каждые 10 минут и ждёт ответа при холодном старте. В GitHub открой **Settings → Secrets and variables → Actions → Variables → New repository variable** и добавь `RENDER_SERVICE_URL` со значением публичного адреса Render, например `https://имя-сервиса.onrender.com` (без `/health`). Workflow не использует токен бота. Расписание GitHub Actions может задерживаться, а Render может перезапустить бесплатный сервис, поэтому непрерывная работа не гарантируется. Одна постоянно работающая служба использует до 744 из 750 бесплатных часов Render в месяце из 31 дня.

## 3. Разреши группу и личку

1. Отправь `/chatid@имя_бота` в своей группе и скопируй отрицательный ID из ответа. Запиши его в `ALLOWED_CHAT_IDS`.
2. С аккаунта, которому нужен доступ в личке, открой бота и отправь `/start`. Пока `OWNER_USER_ID` пустой, бот выводит `Telegram ID для OWNER_USER_ID` в журнал запуска. Возьми положительное число из журнала и впиши в `OWNER_USER_ID`.
3. Примени настройки. На Oracle Cloud после изменения `.env` выполни `sudo docker compose up -d`. На Northflank измени переменные сервиса. Теперь бот будет обрабатывать ссылки только в разрешённой группе и в личке с указанного аккаунта. Изменение `@username` владельца не влияет на доступ.

Проверь, что бот отвечает на Shorts в группе, на фотопост TikTok со звуком и на `@имя_бота Исполнитель — Название` в личке владельца. Затем отправь ссылку в личке с другого аккаунта. В последнем случае бот должен промолчать.

## Ограничения источников и обновление

- Видео и аудио отправляются через стандартный Bot API. Доступный размер файла около 50 МБ. Маленькие совместимые ролики перепаковываются в MP4, большие или несовместимые перекодируются. Если исходник недоступен или файл остаётся слишком большим, бот пишет об этом. [Документация Telegram](https://core.telegram.org/bots/api#sendvideo).
- Для открытых ссылок бот сначала просит Telegram забрать файл прямо с CDN, чтобы не гонять его через Render. Если CDN-ссылка не подходит, бот скачивает файл сам и отправляет через запасной путь. Для YouTube ради скорости приоритетен совместимый ролик до 480p; если такого формата нет, выбирается доступный MP4 и при необходимости он перепаковывается.
- Сайты иногда требуют вход, ограничивают облачные IP или перестают отдавать фото, аудиодорожку либо целый пост. Если Instagram отдаёт только фотографии, бот отправит их. YouTube может ограничить скачивание даже при установленном Deno. [Документация yt-dlp](https://github.com/yt-dlp/yt-dlp/wiki/Extractors).
- Если источник просит вход, в `.env` можно задать `INSTAGRAM_COOKIES_FILE` или `YOUTUBE_COOKIES_FILE`, путь к соответствующему файлу cookies формата Netscape. Храни их отдельно от исходников. В Docker подключи файл как том только для чтения. Внутри контейнера ему нужен доступ на чтение для UID `10001`. На Northflank используй секретный файл. Cookies действуют как вход в аккаунт, поэтому держи их приватными. [Как выгрузить cookies для yt-dlp](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp).
- Если перестал работать отдельный сайт, пересобери образ с актуальными версиями загрузчиков. На Oracle выполни `sudo docker compose build --pull --no-cache && sudo docker compose up -d`. На Northflank пересобери сервис без кеша.

Пример для Oracle Cloud с файлом Instagram cookies в папке `cookies/`. Подставь в `.env` `INSTAGRAM_COOKIES_FILE=/run/media-cookies/instagram.txt`. Дай пользователю контейнера право читать смонтированный файл и создай рядом с `compose.yaml` файл `compose.override.yaml` с этим содержимым.

```yaml
services:
  bot:
    volumes:
      - ./cookies/instagram.txt:/run/media-cookies/instagram.txt:ro
```

## Запуск без Docker на Linux

Нужны Python 3.12+, FFmpeg с `ffprobe` и Deno 2.3+. Создай виртуальное окружение, установи зависимости и запусти бота.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python bot.py
```
